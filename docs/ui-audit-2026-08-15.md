## 二、核心诊断

### 🔴 诊断 1：信息架构「头重脚轻」—— 最高优先

**（a）Overview 顺序反了。** 现状从上到下：

```
① 体检报告横幅（top3 主要矛盾 + 财富等级 + 评分）  ← 先给「问题」
② KPI 数字卡（净资产 / 月结余 / 健康评分）         ← 再给「钱多少」
③ 7 维雷达
④ 目标卡 + AI 洞察
```

你要的是「先告诉我钱怎么样，再告诉我问题在哪，再告诉我怎么办」。现在是**把「最大风险」顶在最前，财富总览数字反而第二** —— 头重脚轻的根源。

**（b）「⑤ 下一步行动」在 Overview 上完全缺失。** `store.actionPlan` 切片（采纳建议 + 完成状态）**已经存在**，但它只挂在 Issues 页里，Overview 没有入口。用户看完体检报告，没有「然后呢」的落点。

**（c）「③ 财富结构」「④ 最近变化」零散。** 结构散在雷达/目标/洞察三处，没有显式「资产/负债/配置」区块；「最近变化」只在数据失效时才弹 stale-banner，无常驻。

**（d）AI 顾问排第 9 位（最后），与「顾问中心化」战略冲突。** 产品战略钉死「顾问是主入口、其余全是能力界面」，但导航里顾问被塞在最末。⚠️ 此条涉及导航顺序，你已声明「不要 nav redo」，故**只作矛盾上报，不动**，由你决策。

### 🟡 诊断 2：组件统一（视觉语言 8 处静默漂移）

`cards.js` 是唯一共享组件库，但**只有 Overview 真正复用**（8 个里用 6 个），Retirement 用 1 个，`AllocationCard` 是死代码。其余页面把同样的 UI 各自手写一遍，且出现漂移：

| # | 漂移点 | 位置 | 现状 |
|---|--------|------|------|
| 1 | 评分色调两套命名 | `HealthScoreCard` 用 `.good/.warn/.bad`，`health.js` 用 `.pos/.warn/.neg` | 绿=`.good` vs `.pos`，红=`.bad` vs `.neg`，颜色相同、名字不同 |
| 2 | 三种「警示琥珀色」 | `health.js` 硬编码 `#ffcc00`，CSS `.dim-score.warn`=`#ff9500`，token `--score-caution`=`#D97706` | 同一个「琥珀」三个 hex |
| 3 | `.change-chip` 定义两次 | `style.css:488`（沙盘，灰底）vs `style.css:571`（chat，金底） | 后者覆盖前者，沙盘的 change-chip 实际渲染成 chat 金色 |
| 4 | `.dim-row/.dim-head` 定义两次 | `style.css:192`（onboarding）vs `style.css:745`（health/风险地图） | onboarding 的 `.dim-row` 意外继承 health 的 top border |
| 5 | 两种「成功绿」 | token `--positive`=`#059669` vs `issues.js`/`.rec-adopted` 硬编码 `#34c759` | `#34c759` 不在 `:root` |
| 6 | chat.js 硬编码颜色绕过 token | `.change-chip`/`.vip-boundary`/`.followup-chip` 直写 hex | 唯一绕过设计 token 的页面 |
| 7 | `.chip` 用法碎片化 | allocation 用 `.chip`，chat 的 `.agent-next .chip` 又覆盖 | 同一「chip」三套样式 |
| 8 | chat.js 内联 `REPORT_CSS` 复制整套设计系统 | `chat.js:295-332` | 导出 HTML 报告自带第二份 CSS，与 style.css 不同步 |

> 结论：**视觉语言没有「失控」，是「没收敛」。** 这些都不是要重设计，是要「归一到既有 token + 删重复定义」——纯减法，风险低。

### 🟡 诊断 3：手机体验（真实用户就在手机上）
