# AI家办 · 人性化设计规范（UX Humanization Spec）

> 目标：让「不懂金融的人」**敢用、看得懂、愿意相信、愿意行动**。
>
> 主 persona：**30–45 岁双职工家庭**（有房贷 + 孩子，三线并行，没时间学）。
>
> 本规范是「四者绝不越权」在体验层的镜像——**不新增公式，不动 Engine/Decision，只改「怎么说、怎么呈现」**。

---

## 元原则：永远告诉用户「下一步」

每一个页面都要回答一个问题：**「所以呢？」** 不要只给结论或只给数字，要给「接下来我能做什么」。

---

## 用户旅程闭环（所有 UX 围绕这一条）

```text
我是谁
 ↓
我的家庭现在怎么样
 ↓
哪里最值得担心
 ↓
为什么
 ↓
如果我什么都不做，会怎样
 ↓
如果我做 A，会怎样
 ↓
如果我做 B，会怎样
 ↓
我应该先做什么
 ↓
执行（MVP = 确认建档动作 / 生成行动计划，非自动金融操作）
 ↓
回来复盘
```

> 「执行 / 复盘」在 MVP 阶段 = 确认建档动作 + 生成行动计划，**不是自动金融操作**——避免悄悄打开 A6 门控。

---

## 10 条铁律

### ① 先结论，后数字

- ❌ 「财富评分 72 · 需关注」
- ✅ **「你的家庭财富状态：整体稳中有忧」** → 下方小字「当前财富评分 72 · 主要需要关注：退休流动资金」

> 不要把「评分」当作第一视觉中心——普通用户会下意识想「为什么我才 72，是不是我很差」。

### ② 先人话，后专业术语

- ❌ 「RFR = 0.48」
- ✅ 「你的家庭净资产不错，但目前大部分财富集中在房产，退休后可灵活使用的资金相对不足。」

### ③ 告诉用户为什么

- ❌ 「建议增加固收配置」（不给理由，用户觉得 AI 在胡说）
- ✅ 「当前金融资产中固收占比约 7%，低于你的个性化目标区间。你的风险画像为『均衡』，建议逐步提高稳定资产比例。**这不是收益预测，而是根据你当前家庭结构和风险画像得出的配置适配建议。**」
- 附：「**依据：资产配置模型 + 当前家庭数据**」

### ④ 每个问题都给下一步

| 位置 | ❌ | ✅ |
|---|---|---|
| X-Ray | 「权益 13%」 | 「权益配置低于你的目标区间」 → **[模拟调整]** |
| 沙盘 | 「RFR 0.72」 | 「这个方案会让你的退休资金安全垫明显下降」 → **[比较其他方案]** |
| 驾驶舱 | 「财富评分 72」 | 「你现在最值得关注的是退休流动资金」 → **[看看为什么]** |

### ⑤ 模拟不会影响真实资产

- 沙盘顶部常驻：「🧪 **沙盘模式**：以下结果仅用于模拟，不会修改你的真实资产数据。」
- 让用户敢点「模拟买房 / 模拟投资 / 模拟提前还贷」。

### ⑥ 允许撤销、回退

- 任何「修改资产 / 目标 / 配置」都要有**撤销** + **恢复到上次状态**。
- 决策历史：

```text
8月14日  模拟：700万买房        → 未执行
8月10日  模拟：50万投资权益      → 未执行
8月2日   调整：应急资金目标      → 已确认
```

> 让产品从「计算器」变成「家庭财富决策档案」。

### ⑦ 减少首次输入成本

- 不要一次让用户填 50 个字段（会直接退出）。
- 3 分钟建财富画像，第一阶段只问 5 个：

```
① 家庭目前有多少资产？
② 每个月收入多少？
③ 每个月大概花多少？
④ 有多少房贷 / 其他负债？
⑤ 家庭未来最重要的目标是什么？
```

- 之后渐进补全：保险 → 教育 → 养老 → 投资 → 家庭成员。
- 画像完整度：**68% → 82% → 95%**，给用户成长感。

### ⑧ 不要制造焦虑 / 降低羞耻感（情绪核心）

财富产品最容易让用户产生羞耻感：看到「评分 48」时，用户想的不是数字，而是「我是不是管理得很差」。

**原则：解释家庭状态，不评价用户。**

- ❌ 「你的资产配置不合理。」（评价人）
- ✅ 「你的家庭目前有 67% 的资产集中在房产，这让总资产看起来比较充足，但退休前真正可以灵活调度的资金相对少。」（解释状态）

> 这与 RFR / NWC 双指标天然契合：说「房产集中度高、可灵活调度资金少」，而不是「你配置错了」。

### ⑨ 重大决策给多个方案，而不是直接命令

- ❌ 「A 72 分 / B 68 分 / C 61 分」
- ✅ 「综合家庭目标后，我们更推荐方案 B」 → **[生成行动计划]**

### ⑩ 所有数字可追溯到 Wealth Engine

- 每个指标都渲染 `source` 为「**依据：XX**」。
- 硬门禁：没有 source 的财富数字不得呈现。

## 建议层：像人，不像报告

机器建议 vs 家办建议的分水岭——**条件化 + 个性化 + 永远不改 Engine 数字**。

- ❌ 「减配现金 / 增配固收」
- ✅ 「你现在不用急着调仓。现金比例确实偏高，但你有 3 年内买房计划，所以这部分现金其实有明确用途。如果买房计划确定，建议先保留这部分资金；如果买房计划取消，再考虑把其中一部分转入固收。」 → **[模拟两种情况]**

> **AI 可以改变表达方式，但不能改变 Engine 的数字。** 事实由 Engine/Decision 产出，Agent 只做「条件化 + 说人话」，LLM 不创造金融建议。

---

## 财富体检报告（铁律①的落地形态）

人们喜欢「体检」，胜过「财务分析」：

```text
现金流      🟢 健康
应急资金    🟢 健康
负债        🟡 需要关注
资产配置    🟡 需要调整
家庭保障    🔴 存在缺口
退休准备    🔴 需要提前规划
```

然后给「**今日最重要的 3 件事**」——用户一眼就知道现在该干什么。

## AI 语气（重要：人性化 ≠ 说话像人）

- ❌ 「您好，我是您的专属 AI 财富顾问，很高兴为您服务……」
- ✅ 知道什么时候该说、什么时候不该说：

| 用户说 | AI 应该说 |
|---|---|
| 「我最近想买房」 | 「可以。我们先看看这笔房贷会不会影响你未来 5 年的现金流和养老准备。」 → **[模拟买房]** |
| 「我最近压力很大」 | 「那我们先不做复杂调整。我可以先帮你看看，目前家庭最需要解决的一件事是什么。」 |

> 不要马上输出 2000 字分析；不要在用户焦虑时继续讲 RFR。

---

## 关联方向（后续阶段，不在本阶段强制）

- **财富地图**：`现在(现金流/资产/房产/投资) / 未来(养老/教育/买房/传承) / 风险(保障/负债/集中度)` 的导航，点击进入对应沙盘。
- **家庭协同**：买房 / 教育 / 养老 / 保障 / 增长 目标，支持「把这个方案发给家人一起讨论」。

---

## 与冻结契约的映射（哪些已实现，缺的只是 UI）

| 铁律 | 引擎 / Agent 现状 | UI 缺口 |
|---|---|---|
| ⑤ 模拟不改数据 | ✅ `compare_scenario` 只读，从不写库 | 标一句「沙盘模式」 |
| ⑥ 撤销 / 回退 | ✅ 确认前从不写库（`profile._PENDING`） | 决策历史 UI |
| ⑩ 数字可追溯 | ✅ `MetricRef` 硬门禁 + `source` 字段 | 把 source 渲染成「依据：XX」 |
| ④ 给下一步 | ✅ AgentResponse 已带 `next_actions` | 渲染成按钮，而非纯文本 |

> 结论：本阶段 ≈ 前端 + 文案 + 少量 Agent 回复塑造。**0 新公式，0 动 Engine/Decision 冻结契约。**
