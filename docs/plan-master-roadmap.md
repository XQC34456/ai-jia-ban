# AI家办 · 主开发路线图（Master Roadmap）

> 本文件是**唯一的主计划总纲**。分阶段 `plan-*.md` 只负责各自阶段的实施细节，冲突时以本文件为准。
>
> 定位：**专业财富管理 × 家庭温度的 AI 家办平台**

---

## 0. 核心原则（铁律，任何阶段不得违反）

| # | 原则 |
|---|---|
| P1 | 财富数字一律由 Wealth Engine / Decision 计算，LLM 绝不计算、绝不编造 |
| P2 | 四者绝不越权：Engine 计算 / Agent 组织 / LLM 语言 / UI 呈现 |
| P3 | 确认之前绝不写数据库 |
| P4 | 所有数字可追溯到 Wealth Engine（`MetricRef.source` 硬门禁） |
| P5 | 一个阶段一个边界，不做「顺手改别的」 |

---

## 1. 目标用户（已钉死）

**主 persona：30–45 岁双职工家庭**

- 有房贷 + 孩子，买房 / 教育 / 养老三线并行
- 有真实决策压力，但没预算请真人理财师
- 有财务焦虑、没时间学 → 需要「敢用、看懂、信、行动」

**心理画像（为什么留下）**：*「我不缺赚钱能力，但越来越不知道重大资金决策该怎么做。」*

> AI家办要解决的不是「算不清账」，而是「决策焦虑 + 无人可问」——这是它与「财富计算器」的分水岭。
> 人性化铁律（见 [spec-ux-humanization.md](spec-ux-humanization.md)）全部对着这一个 persona 验收。

---

## 2. 北极星指标（已钉死）

**北极星：**「画像 → 首次 AI 对话」转化 = 新用户 7 日内完成财富画像，并触发 ≥1 次 AI 顾问对话的比例。

- 这是 aha moment，同时验证「敢投入数据 + 愿和 AI 交互」，最可归因。

**价值发生指标（同等关键）：**「首次有效决策完成率」= 用户完成一次 买房模拟 / 配置调整 / 退休方案 / 还贷 vs 投资 / 目标规划 的比例。

- 防止优化成「AI 很会聊，但用户没做任何决策」——聊天不是价值，决策才是。

**辅助指标**：建档完成率（测铁律⑦）、沙盘周使用次数（测铁律⑤）、7 日留存。
- 测试版阶段的一切改动，都要能归因到北极星 / 价值发生指标 / 辅助指标，否则不做。

## 4. 下一阶段（当前最优先）：体验优化 & 数据治理

> 核心能力已冻结，缺的不是更多公式，而是**让不懂金融的人敢用、看懂、信、行动**。

### 4.1 人性化（设计规范见 [spec-ux-humanization.md](spec-ux-humanization.md)）

10 条铁律 + before/after 验收样例。关键判断：

- 一半铁律是「引擎已做到、UI 没说出来」：模拟不改数据（`compare_scenario` 只读）、确认前不写库（`profile._PENDING`）、source 可追溯（`MetricRef`）、下一步已存在（`next_actions`）。
- **落在前端 + 文案 + 少量 Agent 回复塑造。0 新公式，0 动 Engine/Decision 冻结契约。**

### 4.2 数据治理（分两档）

- **第一档（优先）**：`health_check → build_issues` 统一问题口径，消除「两套结论」风险。
- **第二档**：`monthly_income` 死字段清理 + 前端重复请求收敛（统一走 store）。

### 4.3 冷启动 / 空状态（独立验收场景）

- 全新 0 数据用户，**60 秒内**看到「有意义的反馈」，而不是「先填 50 个字段」。
- 3 分钟建财富画像（5 个核心问题），之后渐进补全，画像完整度 68% → 82% → 95% 成长感。

---

## 5. 测试闸门：B1 / B2

- **B1 手工体验**：7 类意图逐条验证。
- **B2 极限测试**：错误参数 / 缺失参数 / 不存在场景 / 免费调 VIP / LLM 返回错误 JSON / 超时 / 并发……
  - AI 可以笨、可以拒绝、可以让用户补充信息，**但绝不能编造财富数字**。

---

## 6. 数据安全基线（测试版之前，必做）

- 加密存储 + 最小权限 + 数据导出 / 删除权（个保法）。
- 密钥安全：`LLM_API_KEY` 不落前端、不入库、不随响应回传。

---

## 7. 测试版 MVP → 真实用户

- 以「北极星指标 + 辅助指标」为验收标准，不是「感觉」。
- 真实用户 → 问题收集 → **归因到指标再改**。

---

## 8. 阶段门控（重要：A5 / A6 不是既定路线）

- **A5**（上下文 / 解释增强）、**A6**（决策协助）改为**门控**：
  - 只有当测试版数据证明用户真的卡在「上下文接不上 / 不会做决策」时才启动。
  - 否则砍掉。这是给「堆 AI」上的刹车。

---

## 9. 正式版基础设施（后期）

AI Gateway → 多 Provider → 缓存/限流/队列 → 数据库 → 长期记忆 → 主动风险监控 → 商业化。

> 你的服务器承担「AI 调度和产品逻辑」，模型算力交给模型厂商。扩的是 API/Provider/Queue/Cache/DB，不重写 Agent。
