# AI家办 · 主开发路线图（Master Roadmap · 实施版）

> **本文件是实施路线图**（怎么落地）。**战略主纲 = [plan-v10-restructure.md](plan-v10-restructure.md)**（做什么、验收什么）。
> 主线 = **V1.0 产品重构**：从「财报生成器」回到「长期家庭财富 AI 顾问」。本文件把 V1.0 的 Phase 0-8 翻译成可执行的工作项。
>
> 定位：**家庭财富决策操作系统 —— AI 顾问是主入口与决策中枢，不是聊天窗口。**

---

## 0. 核心原则（铁律，任何阶段不得违反）

| # | 原则 |
|---|---|
| P1 | 财富数字一律由 Wealth Engine / Decision 计算，LLM 绝不计算、绝不编造 |
| P2 | 四者绝不越权：Engine 计算 / Agent 组织 / LLM 语言 / UI 呈现 |
| P3 | 确认之前绝不写数据库 |
| P4 | 所有数字可追溯到 Wealth Engine（`MetricRef.source` 硬门禁） |
| P5 | 一个阶段一个边界，不做「顺手改别的」 |

> V1.0 新增交互原则（先回答再建档 / 问题永不丢失 / 不重复问 / 不懂就问 / 先判断再展示）见主纲第五章，与上表同为硬约束。

## 1. 目标用户（已钉死）

**主 persona：30–45 岁双职工家庭**

- 有房贷 + 孩子，买房 / 教育 / 养老三线并行
- 有真实决策压力，但没预算请真人理财师
- 有财务焦虑、没时间学 → 需要「敢用、看懂、信、行动」

**心理画像（为什么留下）**：*「我不缺赚钱能力，但越来越不知道重大资金决策该怎么做。」*

> AI家办要解决的不是「算不清账」，而是「决策焦虑 + 无人可问」。见 [spec-ux-humanization.md](spec-ux-humanization.md)。

---

## 2. 北极星与验收标准（V1.0 对齐）

**第一验收标准（不是 KPI，是产品本质）：** 顾问是否真的像一个可靠的家庭财富顾问。

- 一句话：用户形成稳定认知 —— *「我有任何家庭财富问题，都可以先问 AI 家办。它知道我家；不知道时会问我；不会乱编数字；能告诉我为什么；能把建议变成行动；情况变了还会提醒我重新评估。」*（主纲 §十四）

**质量验收指标（主纲 §九，9 项）**：相关性 / 澄清能力 / 数据复用 / 取消建档 / 数字一致性 / 个性化 / 行动性 / 上下文连续性 / 长期性。每项都有明确验收标准，**替代旧的「一次有效决策完成率」作为主指标**。

**辅助指标（保留）**：建档完成率、沙盘周使用次数、7 日留存。

**决策漏斗（保留，作为归因工具）**：首次理解率 → 有效对话率 → 决策模拟率 → 方案采纳率 → 行动完成率 → 长期留存。每一层归因到具体 Phase（见 §5），否则不做。

## 4. 现状核对 → 真缺口（Phase 1 的开工依据）

> 逐条代码取证见 [verification-v10-current-state.md](verification-v10-current-state.md)。此处只给结论。

**真缺口（4 条，Phase 1 主攻）**：

| 缺口 | 内容 | 用户可见影响 |
|------|------|-------------|
| **G1** | 顾问优先建档而非回答 | 带金额的提问被确认卡吞掉 |
| **G2** | 建档/问答耦合，无独立建档流程 | 只想问问题却被要求建档 |
| **G3** | 取消建档丢原问题 | 「取消建档 = 问题被中断」 |
| **G4** | 无澄清循环 | 不理解时硬答或兜底 Overview |

**部分成立（Phase 2/3 收）**：论断 #4（数据复用，建档路径不查已有数据）、#6（工具调用，P1.1 已缓解但证据 claim 仍自由）。

**不成立（不修）**：论断 #7（财报/图表主导）——顾问已结论先行，**明确排除出修复范围**，避免反向优化。

**已有基础（复用，不重造）**：P1.1 `_with_baseline`（确定性基线）、P1.3 `follow_up_questions`（缺数检测）、V2.4 三层记忆 L2、结论先行 + 图表限 1-2 张、确认卡 `_PENDING`。

> 每个 Phase 对应主纲 §十；「映射旧主线」列帮助对接已归档的历史计划，避免命名混乱。

| V1.0 Phase | 目标 | 核心工作 | 映射旧主线 | 服务缺口 | 状态 |
|------------|------|----------|-----------|---------|------|
| **Phase 0** 冻结主线 | 确立主线 | Advisor-first / 问答建档解耦 / 数据复用 | 本文件 + 主纲落定 | 全部 | ✅ 本批次 |
| **Phase 1** 顾问核心重构 | 顾问像顾问 | Intent/Context/Clarify/Answer/Action 状态机；问题不丢失；取消建档继续回答；AdvisorContext 契约；Advisor Benchmark | 新（V2.3 状态机扩展 + P1.3） | **G1 G2 G3 G4** | 📍 **下一步** |
| **Phase 2** 家庭数据智能复用 | 不重复问 | 档案查询 / 增量建档 / 字段冲突 / 来源追踪 / 缺数检测 | V2.1 Context 扩展 + V2.4 记忆 | 论断 #4 | 待办 |
| **Phase 3** 顾问推理层 | 数字稳定 | Advisor→Engine→Scenario→Decision 统一编排；必需证据确定性预取 | P1.1 扩展 | 论断 #6 | 待办 |
| **Phase 4** 建议与行动 | 行动闭环 | 建议 → 模拟 → 计划 → 采纳 → 完成 → 复评 | V2.6 Action Loop | — | 待办 |
| **Phase 5** 长期顾问 | 二次回来理由 | stale / 变化检测 / 主动提醒 / 重新评估 / 历史比较 | V2.5 Proactive（需调度器） | — | 待办 |
| **Phase 6** 可视化证据层 | 图表服务答案 | 按回答动态挂载图表/财报/字段证据 | product-matrix-v26（降级为从属） | — | 待办 |
| **Phase 7** 商业化 | 核心价值后再优化 | Free/VIP 边界优化 | P2-A 扩展 | — | 待办 |
| **Phase 8** 对标验证 | 可追溯领先 | 固定 12 问 prompt，与 DeepSeek 盲测 + rubric | P2-B 正式对标 | — | 待办 |

### Phase 1 具体范围（V1.0 §十五「只做一件事」）

1. **Advisor Benchmark**：主纲 §十一 的 12 个真实问题 → 建立回归用例（每题记录 intent / 是否直接回答 / 是否澄清 / 确定性工具 / 关键数字 / 证据路径 / 行动建议）。
2. **AdvisorContext 契约**：结构化上下文传递（主纲 §八），替代纯文本 draft 预填。
3. **两条路径优先重构**：
   - 跨页面问顾问：Goals/Retirement/Allocation/Sandbox/Overview 入口 → 结构化 AdvisorContext → 第一轮直接回答入口问题。
   - 取消建档后继续回答：确认卡取消 → 原问题不丢 → 继续回答（G3 主战场）。

> 验收（主纲 §九）：「完整链路跑通：用户提出问题 → 顾问理解 → 直接回答 → 必要时澄清 → 复用已有数据 → 需要时增量建档 → 个性化判断 → 可视化证据 → 行动计划 → 后续变化触发复评。」
